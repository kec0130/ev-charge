# 헤르메스 콘텐츠 작업안

이 문서는 향후 헤르메스에 연결할 실행 규격이다. 현재 PC 접속, 크론 등록, 자동 발행 구현은 하지 않았다. 기존 MDX 게시 구조에 맞춰 사람이 확인할 수 있는 초안부터 자동화한다.

## 파일과 게시 경계

- `posts/*.mdx`: 현재 공개 대상. 이 폴더에 초안을 넣으면 빌드에 포함된다.
- `drafts/*.mdx`: 초안용으로 제안하는 폴더. Contentlayer의 `contentDirPath: posts` 밖이므로 게시 대상이 아니다.
- `drafts/<slug>.review.json`: 초안의 출처·검토 기록. MDX 본문과 별도로 보관한다.
- 현재 Contentlayer는 `title`, `description`, `keywords`, `created_at`을 요구한다. 아직 지원하지 않는 `draft`, `reviewed_at` 필드에 공개 차단을 의존하지 않는다.

## 권장 작업 순서

1. 주 1회: Search Console 질문과 이용자 불편을 기존 글 제목·질문과 비교한다. 겹치면 신작 대신 기존 글 갱신 후보로 만든다.
2. 자료 수집: 정부·지자체·제조사·사업자 원문을 우선한다. 각 자료의 게시일, 적용일, 확인일, 대상 조건을 별도로 기록한다. 뉴스는 원문을 찾는 단서로 사용한다.
3. 초안 생성: 질문 하나에 답하고, 직접 만든 비교표·계산 예시·확인 순서를 최소 하나 넣는다. 근거 없는 체험담이나 수익·가격·보조금 수치를 만들지 않는다.
4. 자동 검사: MDX 필수 필드, 중복 slug, 내부 링크와 이미지 존재, 출처 링크 응답, 숫자·단위·날짜, 미완성 표식을 확인한다. HTTP 200을 사실 검증 완료로 간주하지 않는다.
5. 사람 검토: 수치와 적용 조건을 원문과 비교하고, 독자가 실제로 행동할 수 있는지 확인한다. 비용·지원 제도·안전 관련 안내는 특히 원문을 확인한다.
6. 게시 준비: 검토된 MDX를 `posts/`로 옮기고 `npm test`, `npm run lint`, `npm run build`와 화면 확인을 실행한다. 새 사진은 사용 권한을 확인한다.
7. 게시 후: 페이지 색인·검색어·관련 도구 이동·수익을 확인한다. 원문이 바뀌면 해당 주장을 사용하는 글만 재검토 대상으로 만든다.

## 현행 스키마로 작성 가능한 초안 형태

아래는 형식 예시이며, 그대로 게시할 글은 아니다. 완성 전에는 `drafts/`에 둔다.

```mdx
---
title: '지도에 뜨는 충전소의 출입 조건을 확인하는 방법'
description: '충전기 상태와 출입 제한을 구분하고, 방문 전 확인할 항목을 정리합니다.'
keywords: '전기차 충전소, 이용제한, 외부인 충전'
created_at: 2026-09-14
---

독자의 질문에 대한 짧은 답을 먼저 작성합니다.

### 방문 전 확인 순서

공식 자료를 확인한 뒤 충전 상태, 이용 가능 대상, 운영시간, 주차요금을 구분합니다.

### 상황별 예시

출처로 확인한 사실과 설명을 위해 가정한 예시를 명확히 나눕니다.

### 출처와 확인일

검토한 실제 원문 링크, 적용 시점과 마지막 확인일을 기록합니다.
```

검토 기록 형식 예시:

```json
{
  "slug": "charger-access-guide",
  "status": "draft",
  "question": "충전 가능한 상태인데도 왜 출입이 안 되나요?",
  "checked_at": null,
  "next_review_at": null,
  "sources": [],
  "claims": [],
  "reviewer": null,
  "automation": "자료 정리와 초안 작성에 사용"
}
```

`sources`에는 원문 URL·제목·게시일·적용일·확인일을, `claims`에는 주장·대응 출처·수치·단위·적용 조건을 넣는다. 이 JSON을 읽어 검사를 실행하는 코드는 아직 구현되지 않았다.

## 점검 주기와 중단 조건

| 종류 | 최초 권장 점검 주기 | 발행 조건 |
| --- | --- | --- |
| 충전 원리·사용법 | 분기별 또는 설명서 변경 때 | 사용설명서와 일치, 독자가 따라갈 수 있는 절차 |
| 사업자 요금 | 월 1회와 공지 변경 때 | 확인일·회원/비회원·로밍 등 조건 명시 |
| 보조금·세금 | 해당 연도 공고·예산·제도 변경 때 | 지역·기간·대상 조건과 공식 원문 검토 |
| 차량 가격·출시일 | 제조사 발표 때 | 예상·발표·판매 중 상태를 구분 |
| 출입 관련 안내 | 신고 또는 시설 변경 때 | 해당 시설·운영기관의 최신 조건 확인 |

확인할 출처가 없거나 자료끼리 충돌하면 초안으로 남긴다. 자동 수집 실패 시 오래된 수치를 최신 날짜로 다시 발행하지 않는다. 여러 사이트의 문장을 조합하는 것만으로 새 글을 만들지 않는다. 생성형 AI 활용은 독자에게 도움이 되는 방식으로 제작 과정에 설명한다. [Google 생성형 AI 콘텐츠 가이드](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content)

첫 운영은 주 1~2편을 상한으로 두고 실제 검수 시간을 기록한다. 주제별 검색 반응과 검수 부담을 확인한 뒤 늘린다. 글감 후보 12개와 우선순위는 [재운영 분석](revival-plan.md)에 있다.
