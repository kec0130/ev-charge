# 전기차G 재운영 분석 · 2026-09-14

추천 방향은 **‘처음 전기차를 사거나 충전하는 사람이 실제로 겪는 문제를 해결하는 사이트’**다. 충전 지도를 고쳐 신뢰를 회복하고, 충전·유지비·중고 구매 준비 콘텐츠를 검색 유입의 중심으로 삼는다. 중고 매물 가격을 매달 수작업으로 모으는 운영은 보류하고 기존 자료를 과거 기록으로 보존한다.

현재 방문자, 검색어, 페이지별 애드센스 수익, 운영 비용은 확인되지 않았다. 아래 우선순위는 코드·공개 사이트·실제 공공 API 표본에 근거한 판단이며, 트래픽이나 수익 증가 예측은 아니다. 전기차 시장의 성장과 이 사이트의 검색 유입 증가는 별도로 검증해야 한다.

## 1. 확인된 문제와 의미

| 영역 | 확인한 사실 | 의미 |
| --- | --- | --- |
| 충전소 접근성 | API 원본의 `limitYn`을 버리고, 빈 `limitDetail`을 화면에서 ‘없음’으로 표시 | 실제 이용 제한을 놓치게 하는 직접적인 원인 |
| 충전 상태 필터 | 급속 보유와 빈 충전기 존재를 따로 판단 | 급속은 사용 중인데 완속만 비어 있는 충전소가 ‘급속+충전가능’에 노출 |
| 데이터 정합성 | 삭제 표시 미처리, 첫 9,999개만 조회, 예외에서 `e.response`에 무조건 접근 | 삭제된 위치 표시, 데이터가 많은 지역 누락, 통신 실패 시 추가 예외 가능 |
| 지도 갱신 | 마커의 좌표·타입 변경이 effect에 반영되지 않음 | 데이터가 바뀌어도 지도 표시가 갱신되지 않을 수 있음 |
| 중고시세 | 기간 생성과 기본 이동 대상이 2024-05에서 멈춤 | 방문자가 현재 가격으로 해석하면 신뢰 손상 |
| 가격 자료의 의미 | 차종별 최저·최고 가격 중심 | 표본 수·연식·트림을 통제한 가격 분포나 실거래 통계로 볼 수 없음 |
| 블로그 | MDX 12편, 모두 2023년 작성. 보조금·취득세·차량 가격·출시 일정 포함 | 자동 신작 생산보다 기존 유입 글의 정확성 재검토가 먼저 |
| 블로그 성능 | 목록 페이지 JSON에 모든 글의 본문까지 포함, 로컬 빌드에서 574,212바이트 | 글이 늘수록 목록과 관련 글의 불필요한 전송량 증가 |
| 검색 메타데이터 | canonical 없음, 중고시세 월별 페이지도 동일한 `/used-cars` URL 사용 | 각 페이지의 주소·주제 표현 정리 필요 |
| 검색 갱신 신호 | 내용 변경과 관계없이 사이트맵의 일부 `lastmod`를 현재 시각으로 생성 | 검색엔진에 실제 변경 시점을 전달하지 못함 |
| 기술 유지관리 | 잠금 파일 기준 Next.js 13.5.11, Contentlayer 0.3.4. Next 14 전환 후 되돌린 이력 존재 | 프레임워크 전환은 별도 호환성 작업으로 진행할 필요 |

실제 2026-09-14 서울 중구(`11140`) 원본 API 조회에서는 **충전기 기록 1,991개 중 878개가 `limitYn=Y`**, 35개가 삭제 표시였다. 이 수치는 충전소 수가 아니고 전국 대표 표본도 아니다. 수정한 집계로는 삭제 등을 제외한 충전기 1,956개, 충전소 375곳이 반환됐다. 그중 제한 없음 196곳, 제한 있음 147곳, 확인 필요 32곳으로 분류됐다. 상태는 조회 시점에 따라 변할 수 있다. 제공 기관은 이용자 제한 여부와 삭제 여부 등을 API 제공 항목으로 명시한다. [한국환경공단 API 안내](https://www.data.go.kr/data/15076352/openapi.do)

## 2. 세 기능의 역할을 다시 정하기

| 기능 | 추천 역할 | 당분간 운영 방식 | 확대 기준 |
| --- | --- | --- | --- |
| 충전 지도 | 사이트의 실용 도구와 재방문 이유 | 접근성·정확성 개선에 집중 | 오류율 감소, 실제 이용, 재방문이 확인될 때 지역 안내 확장 |
| 전기차 블로그 | 검색 유입과 광고 수익의 중심 후보 | 주 1~2편의 문제 해결 글 + 기존 글 점검 | 색인·노출·클릭이 발생하는 주제부터 확대 |
| 중고시세 | 과거 차종·가격 범위 참고 자료 | 조사 시점 표시, 신규 수집 중단 유지 | 지속 가능한 제공처와 비교 가능한 표본 설계가 확보될 때 재개 |

지도만으로 규모를 키우려면 위치·상태 외에 이용자가 신뢰할 수 있는 출입 정보가 필요하다. 과거 사용자 불만이 이미 이 차별화 지점을 보여준다. 지도와 글을 연결하면 ‘외부인도 가능한 충전소를 찾는 방법’을 읽은 사람이 바로 도구를 사용하고, 지도 사용 중 생긴 질문이 다음 글감이 될 수 있다. 현재 코드에는 검색 가능한 개별 충전소 상세 URL이 없으므로, 지도에 마커를 많이 표시한다고 충전소별 검색 페이지가 늘어나는 구조도 아니다.

**중고시세는 최저·최고값만 모아 재가동하지 않는 편을 권한다.** 데이터 접근·이용 조건을 확인하고, 동일 차종/연식/주행거리/트림 기준, 중복 제거, 표본 수, 수집 일자, 출처, 중앙값·분위수를 정할 수 있을 때 재개한다. 매물 호가와 실거래가를 구분한다. 그 전에는 ‘예산별 중고 EV 후보와 확인할 항목’ 같은 구매 준비 글이 운영 부담에 더 잘 맞는다. 가격 수치를 쓰는 글은 최신 출처를 확인한 날짜를 명시한다.

기존 비전기차 글은 유입·외부 링크를 보기 전 일괄 삭제하지 않는다. 유지할 가치가 있는 글은 보존하고, 새 콘텐츠와 내부 연결의 중심을 전기차 생활로 좁힌다.

## 3. 헤르메스 자동화의 범위

전용 PC의 가장 큰 장점은 글 수를 늘리는 속도보다 **자료를 계속 확인하고 업데이트 대상을 찾아낼 수 있다는 점**이다. 1차 자동화는 자료 수집, 중복 글감 탐지, 초안, 출처·링크 검사, 변경 감지까지 담당하게 한다. 초안은 `posts/` 밖에 저장한다. 현재 이 프로젝트는 `posts/`의 모든 MDX를 게시 대상으로 취급한다.

추천 순서: 공식 자료 수집 → 독자의 질문 하나 선정 → 출처별 주장 기록 → MDX 초안 → 수치·적용 조건·이미지 이용 가능 여부 검토 → 빌드와 미리보기 → 게시 → 출처 변경 감지.

Google은 생성형 AI를 조사와 원본 콘텐츠 구성에 활용할 수 있다고 설명하지만, 사용자에게 부가 가치를 주지 않는 페이지의 대량 생성은 스팸 정책에 해당할 수 있다고 명시한다. 따라서 ‘AI 작성 여부’보다 질문을 해결하는 정보·근거·검수가 핵심이다. 자동화를 이유로 발행 수를 먼저 늘리지 않는다. [Google 생성형 AI 콘텐츠 안내](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content)

운영 규칙과 초안 형식은 [헤르메스 작업안](hermes-content-workflow.md)에 정리했다. 이는 구현 제안이며, 이번 작업에서 헤르메스 PC 연결·스케줄 등록·자동 발행은 수행하지 않았다.

검색량이 확인된 키워드 목록이 아니라, 기존 도구·실제 불편과 연결되는 편집 후보들이다. Search Console에서 이미 노출되는 질문이 있으면 그 질문을 우선한다.

1~6번을 먼저 검증한다. 보조금·세금·실시간 요금표는 갱신 부담이 크므로 지속적인 점검을 붙일 수 있을 때 확대한다. ‘충전비 계산기’는 데이터 수집 부담이 낮아 다음 기능 후보로 추천하지만, 입력값과 충전 손실 등 가정을 명확히 해야 한다.

## 5. 수익을 판단하는 방법

월 광고수익의 단순 계산은 `월 페이지뷰 ÷ 1,000 × 페이지 RPM`이다. 예를 들어 페이지 RPM을 **가정상 2,000원**으로 고정하면 1만 PV는 2만원, 5만 PV는 10만원, 15만 PV는 30만원이다. 이 값은 이 사이트의 실적이나 업계 평균이 아니다. 방문자 수와 페이지뷰도 다르다.

광고 개수보다 먼저 확인할 값은 다음과 같다.

- Search Console: 최근 90일의 페이지·검색어별 노출, 클릭, CTR, 색인 현황. 평균순위만으로 성패를 판단하지 않는다.
- GA4: 페이지별 자연검색 유입, 참여, 재방문. 블로그→지도 이동이 실제로 일어나는지 확인한다.
- AdSense: 지도·블로그·중고 기록의 페이지뷰, 페이지 RPM, 수익, 광고 노출률과 정책 알림.
- 운영 비용: 호스팅·지도 API·생성 모델·전기요금의 증가분과 매주 실제 검수 시간.

수익성은 총수익뿐 아니라 **추가 수익 − 추가 비용**과 운영 시간으로 판단한다. 이미 보유한 PC도 전기와 모델 호출 비용은 들 수 있다. 서로 다른 주제의 수익성은 조회수가 충분히 쌓인 뒤 비교한다.

지도와 바텀시트는 사용자가 손가락으로 조작하는 영역이다. 광고를 늘리거나 고정 배치를 바꾸기 전 모바일에서 버튼·목록과의 거리를 확인해야 한다. 현재 광고 배치를 정책 위반이라고 단정할 근거는 없으며, 이번 변경에서는 광고 슬롯을 늘리지 않았다. Google은 탐색 요소 근처의 광고가 의도하지 않은 클릭을 만들 수 있다고 안내한다. [애드센스 게재위치 정책](https://support.google.com/adsense/answer/1346295?hl=ko)

| 5~8주 | 노출되는 질문 보강, 충전비 계산기 또는 출입정보 신고 기능 중 하나 선택 | 실제 검색·사용 데이터로 다음 기능의 필요성을 설명할 수 있음 |
| 9~12주 | 주제별 검색 클릭·수익·운영 시간을 비교해 발행 범위 조정 | 효과 있는 주제에 집중하고 갱신 부담만 큰 작업을 줄임 |

우선 주 1~2편은 운영 실험을 위한 제안이다. 사용자의 가용 시간은 아직 확인되지 않았다. 주당 시간이 적으면 신작 수보다 기존 유입 글의 검토를 우선한다. 초기 트래픽이 작으면 90일은 수익을 확정하는 기간이 아니라 운영 지속성과 검색 반응을 확인하는 기간으로 본다.

## 7. 이번에 구현한 것

- 지도 기본 필터: `limitYn=N`이고 제한 설명에 충돌이 없는 충전소만 표시. 제한·미확인은 필터 해제 시 구분 표시.
- 동일 충전소의 여러 충전기 중 제한이 하나라도 있으면 보수적으로 제한으로 합침. 시설 이름만 보고 아파트 전체를 차단하는 방식은 사용하지 않음.
- 삭제·중복·유효하지 않은 좌표 제외, 급속과 충전가능 조건을 동일 충전기에서 평가, 조건에 맞는 마커 갱신.
- 제한 설명이 없다는 이유로 ‘없음’이라고 단정하던 표시 수정, 필터 결과 0곳과 API 실패 구분.
- HTTPS, 타임아웃, 페이지 조회, 응답 오류 처리, 잘못된 입력·요청 방식 검증.
- 위치 요청 타임아웃, 권한 거부 시 현 위치 마커와 ‘내 주변’ 안내의 오해 방지.
- 중고 가격 기록의 기준 월·과거 자료 안내, 월별 canonical, 배열 정렬에 따른 상태 갱신 버그 수정.
- 블로그 목록·관련 글에서 본문 전송 제거, 관련 글을 키워드 겹침 기준으로 선택, 원본 작성 시점 안내.
- 같은 12편 기준 목록 JSON이 574,212바이트에서 6,728바이트로 약 98.8% 감소. 압축 전 페이지 데이터 비교이며 이미지·공통 JavaScript를 포함한 전체 용량이나 체감 속도 측정은 아님.
- canonical·공유 이미지의 절대 URL, 부정확한 사이트맵 갱신시각 제거, Contentlayer 중복 실행 제거.
- 충전소 분류와 API 응답 처리에 대한 회귀 테스트.

사이트맵의 `lastmod`는 실질적인 내용 변경 시점을 반영해야 한다는 Google 안내에 맞춰, 요청 때마다 현재 날짜를 넣던 부분을 제거했다. 실제 본문 갱신일을 별도로 저장하는 기능은 후속 작업이다. [Google 사이트맵 안내](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)

## 8. 남은 한계와 다음 기술 작업

공공데이터만으로 모든 현장 제한을 보장할 수 없다. `N`과 모호한 설명이 함께 있는 경우에는 ‘확인 필요’로 두어 기본 노출에서 제외한다. 공개 시설 일부가 보수적으로 제외될 수 있으며, 필터 해제로 확인할 수 있다. 이를 개선하려면 충전소 ID별 신고 근거·검토 상태·확인일·만료일을 저장하는 정정 기능을 추가한다. 신고 접수 즉시 영구 차단하기보다 검토 후 반영하고, 오래된 정정은 재확인한다.

현재 충전 상태는 방문·재조회 시점에 가져온다. 이번에 장시간 열린 지도의 주기적 상태 갱신이나 서버 공유 캐시는 추가하지 않았다. 이용량을 확인한 뒤 지역별 정보 캐시와 상태 갱신을 분리하는 것이 다음 과제다. 공공데이터의 `statUpdDt`는 상태 변경 시각이므로, 오래된 값이라는 이유만으로 곧바로 통신 장애라고 판단해서는 안 된다.

행정구역 코드와 충전기 타입은 하드코딩되어 있다. 실제 표본에서 기존 표에 없는 `10` 타입도 확인했다. 미지원 타입을 무조건 급속이라고 하던 처리는 고쳤고, 상세에서는 확인 필요로 표시한다. 최신 공식 코드 전체의 반영과 지역 선택·역지오코딩의 전국 검증은 별도 작업으로 남는다.

Next.js 13은 공식 지원 대상 밖이다. 대규모 콘텐츠 자동화를 붙이기 전에 지원 버전으로 이전해야 한다. 이 프로젝트는 Pages Router이며 App Router 전용 보안 공지를 그대로 적용해 취약하다고 단정하지 않는다. Contentlayer, Chakra, React, Node와 함께 호환성을 점검하고 업그레이드한다. [Next.js 지원 정책](https://nextjs.org/support-policy)

충전소 리뷰는 브라우저에서 Supabase에 쓰는 구조다. 리뷰 확장 전 실제 RLS·스팸 제한·오류 처리를 점검해야 한다. 이번에는 운영 데이터베이스 정책이나 리뷰 데이터를 변경하지 않았다.

배포 환경에는 서버 전용 `EV_CHARGER_SERVICE_KEY` 사용을 권장한다. 기존 `NEXT_PUBLIC_API_SERVICE_KEY`도 호환을 위해 읽으므로 환경변수 이름 변경 없이 이번 코드를 시험할 수 있다. 새 서버 전용 변수를 설정하고 검증한 뒤 옛 이름을 정리한다. 원격 배포·계정 설정 변경은 이번 작업에 포함하지 않았다.

검증: 회귀 테스트 14개·린트·프로덕션 빌드(25개 정적 페이지) 및 로컬 HTTP 응답을 확인했다. API 입력 오류 400, 지원하지 않는 메서드 405, 블로그·중고 가격·사이트맵 200을 확인했고, 생성된 HTML의 canonical과 과거 자료 안내도 검사했다. 로컬 실행기는 Node 26으로 확인됐으며, package.json의 배포 목표는 Node 22이므로 배포 미리보기에서도 확인할 필요가 있다. 브라우저 제어 도구에 사용 가능한 브라우저가 없어 실제 지도 렌더링, 모바일 터치, 광고의 시각 배치는 확인하지 못했다. 배포 전 대표 모바일 화면 검수가 남아 있다.
